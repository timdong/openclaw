# OpenClaw 项目培训手册

本文档基于项目官方文档整理，面向新成员和贡献者，帮助快速理解 OpenClaw 的架构、安装、配置与开发流程。

---

## 一、项目概述

**OpenClaw** 是一款**个人 AI 助手**，运行在你自己的设备上。它在你已有的聊天渠道上与你对话（WhatsApp、Telegram、Slack、Discord、Google Chat、Signal、iMessage、Microsoft Teams、WebChat 等），并支持扩展渠道（BlueBubbles、Matrix、Zalo 等）。网关是控制面，产品形态是助手。

- **官网**: https://openclaw.ai  
- **文档**: https://docs.openclaw.ai  
- **仓库**: https://github.com/openclaw/openclaw  

**推荐入门方式**：运行入门向导 `openclaw onboard`，它会引导完成网关、工作区、渠道和技能配置。CLI 向导在 **macOS、Linux、Windows（WSL2 强烈推荐）** 上均可使用。

---

## 二、核心概念

### 2.1 架构概览

- **单一长期运行的 Gateway** 拥有所有消息面（WhatsApp/Baileys、Telegram/grammY、Slack、Discord、Signal、iMessage、WebChat 等）。
- **控制面客户端**（macOS 应用、CLI、Web UI、自动化）通过 **WebSocket** 连接网关，默认绑定 `127.0.0.1:18789`。
- **节点**（macOS/iOS/Android/无头）也通过 WebSocket 连接，但声明 `role: node` 及能力/命令。
- **每台主机一个 Gateway**；它是唯一打开 WhatsApp 会话的地方。
- **Canvas 主机**（默认 18793）提供 Agent 可编辑的 HTML 和 A2UI。

### 2.2 网关（Gateway）

- 维护各渠道连接。
- 暴露类型化的 WS API（请求、响应、服务端推送事件）。
- 对入站帧做 JSON Schema 校验。
- 发出 `agent`、`chat`、`presence`、`health`、`heartbeat`、`cron` 等事件。

### 2.3 Agent 运行时

- 基于 **pi-mono** 的嵌入式 Agent 运行时。
- **工作区**（`agents.defaults.workspace`）是 Agent 唯一的工作目录（工具与上下文的 cwd）。
- **引导文件**（在工作区内）：`AGENTS.md`、`SOUL.md`、`TOOLS.md`、`BOOTSTRAP.md`、`IDENTITY.md`、`USER.md`。新会话首轮会注入这些内容。
- **技能** 来自三处：内置、托管目录 `~/.openclaw/skills`、工作区 `<workspace>/skills`（重名时工作区优先）。

### 2.4 会话（Session）

- **主会话**：每个 Agent 一个直接聊天会话，对应 `agent:<agentId>:<mainKey>`（默认 `main`）；群组/频道有独立 key。
- **状态位置**：网关主机上 `~/.openclaw/agents/<agentId>/sessions/sessions.json` 与 `.../sessions/<SessionId>.jsonl`。
- **DM 范围**（`session.dmScope`）：`main`（默认）、`per-peer`、`per-channel-peer`、`per-account-channel-peer`。
- **重置策略**：默认每日 4:00 本地时间重置；可配置 `idleMinutes`、`resetByType`、`resetByChannel`；支持 `/new`、`/reset` 手动重置。

## 三、安装与快速开始

### 3.1 环境要求

- **Node ≥22**
- macOS / Linux / Windows（建议 **WSL2**）
- 从源码构建时需 `pnpm`

### 3.2 推荐安装（安装脚本）

```bash
curl -fsSL https://openclaw.bot/install.sh | bash
```

Windows PowerShell：

```powershell
iwr -useb https://openclaw.ai/install.ps1 | iex
```

### 3.3 手动全局安装

```bash
npm install -g openclaw@latest
# 或
pnpm add -g openclaw@latest

openclaw onboard --install-daemon
```

向导会安装网关守护进程（launchd/systemd 用户服务），保持常驻。

### 3.4 快速验证流程

1. **运行向导并安装守护进程**  
   `openclaw onboard --install-daemon`

2. **确认网关状态**  
   `openclaw gateway status`  
   或前台运行：`openclaw gateway --port 18789 --verbose`

3. **控制台/仪表盘**  
   本地：`http://127.0.0.1:18789/`  
   或：`openclaw dashboard`

4. **发一条测试消息**  
   `openclaw message send --target +15555550123 --message "Hello from OpenClaw"`  
   或与助手对话：`openclaw agent --message "Ship checklist" --thinking high`

5. **健康与安全检查**  
   `openclaw status`、`openclaw health`、`openclaw security audit --deep`

## 四、向导与配置

### 4.1 入门向导（onboard）

```bash
openclaw onboard --install-daemon
```

向导会引导：

- 本地 / 远程网关
- 模型与鉴权（OAuth 或 API Key；Anthropic 推荐 API Key）
- 渠道（WhatsApp 扫码、Telegram/Discord Bot Token 等）
- 守护进程安装（launchd/systemd；WSL2 用 systemd）
- 网关 Token（向导可自动生成并写入 `gateway.auth.token`）

**鉴权存储位置**：

- OAuth 凭证（旧）：`~/.openclaw/credentials/oauth.json`
- 鉴权配置（按 Agent）：`~/.openclaw/agents/<agentId>/agent/auth-profiles.json`

无头服务器建议：在本地完成 OAuth，再把 `oauth.json` 拷到网关主机。

### 4.2 配置命令

- **交互式配置**：`openclaw configure`（模型、渠道、技能、网关）
- **读写配置**：  
  - `openclaw config get <path>`  
  - `openclaw config set <path> <value>`  
  - `openclaw config unset <path>`
- **健康与修复**：`openclaw doctor`（可加 `--deep` 做更深检查）

## 五、网关服务

### 5.1 运行方式

- **前台**：`openclaw gateway --port 18789 --verbose`
- **服务管理**：  
  - `openclaw gateway status`  
  - `openclaw gateway install | start | stop | restart`  
  - `openclaw logs --follow`

### 5.2 配置热重载

- 默认监听 `~/.openclaw/openclaw.json`（或 `OPENCLAW_CONFIG_PATH`）。
- 默认 `gateway.reload.mode="hybrid"`：安全变更热生效，关键变更需重启。
- 可用 SIGUSR1 触发进程内重启（在启用相应命令时）。

### 5.3 端口与 HTTP 服务

- 默认端口 **18789**：WebSocket 控制面 + HTTP（Control UI、hooks、A2UI）。
- 同一端口提供：  
  - OpenAI Chat Completions：`/v1/chat/completions`  
  - OpenResponses：`/v1/responses`  
  - Tools Invoke：`/tools/invoke`
- Canvas 文件服务默认在 **18793**，可从配置或环境关闭。

### 5.4 远程访问

- 推荐：Tailscale 或 VPN。
- 或 SSH 隧道：  
  `ssh -N -L 18789:127.0.0.1:18789 user@host`  
  客户端连 `ws://127.0.0.1:18789`，若配置了 Token 需在 `connect.params.auth.token` 中带上。

### 5.5 开发/隔离实例（--dev）

```bash
openclaw --dev setup
openclaw --dev gateway --allow-unconfigured
openclaw --dev status
openclaw --dev health
```

使用独立目录 `~/.openclaw-dev` 和不同端口，不影响主配置。

## 六、渠道（Channels）

### 6.1 支持的渠道

| 类型     | 说明 |
|----------|------|
| WhatsApp | Baileys，需扫码配对 |
| Telegram | grammY Bot API，群组支持 |
| Discord  | discord.js |
| Slack    | Bolt |
| Google Chat | Chat API |
| Signal   | signal-cli |
| iMessage | 推荐 BlueBubbles；或原生 imsg（仅 macOS） |
| WebChat  | 网关自带 WebChat UI |
| 扩展     | BlueBubbles、Mattermost、MS Teams、Matrix、Zalo、Nostr 等（部分需单独安装插件） |

### 6.2 渠道管理

- `openclaw channels list` — 已配置渠道与鉴权概要  
- `openclaw channels status` — 可达性与健康（加 `--probe` 做更多检查）  
- `openclaw channels add` — 向导添加渠道  
- `openclaw channels login` — 例如 WhatsApp 扫码  
- `openclaw channels remove` — 禁用或删除配置  

### 6.3 DM 安全与配对

- 默认：未知 DM 会收到**配对码**，在批准前消息不会被处理。
- 批准配对：  
  `openclaw pairing list <channel>`  
  `openclaw pairing approve <channel> <code>`
- 若希望完全开放 DM，需在配置中显式设置 `dmPolicy="open"` 并配置 allowlist（不推荐随意开放）。

## 七、CLI 常用命令速查

| 场景         | 命令 |
|--------------|------|
| 安装与向导   | `openclaw onboard --install-daemon` |
| 配置         | `openclaw configure`，`openclaw config get/set/unset` |

## 八、从源码开发与测试

### 8.1 从源码运行

```bash
git clone https://github.com/openclaw/openclaw.git
cd openclaw
pnpm install
pnpm ui:build   # 首次会安装 UI 依赖
pnpm build
openclaw onboard --install-daemon
```

开发时可用：`pnpm openclaw ...` 直接跑 TypeScript；网关热重载：`pnpm gateway:watch`。

### 8.2 项目结构（简要）

- **源码**：`src/`（CLI 在 `src/cli`，命令在 `src/commands`，网关/渠道等在对应子目录）
- **测试**：与源码同目录的 `*.test.ts`；e2e 用 `*.e2e.test.ts`
- **文档**：`docs/`，构建输出在 `dist/`
- **插件/扩展**：`extensions/*`，插件专用依赖写在插件自己的 `package.json`

### 8.3 测试命令

- `pnpm test` — Vitest 单元/集成测试  
- `pnpm test:coverage` — 覆盖率（约 70% 线/分支/函数/语句）  
- `pnpm test:force` — 清理占用端口的进程后用独立端口跑全量测试  
- `pnpm test:live` — 需要真实 API Key 的 live 测试（如 `LIVE=1`）  
- 详细说明见文档 [Testing](/reference/test) 与 [Testing](/testing)（如存在）。

### 8.4 代码风格与提交流程

- 语言：TypeScript (ESM)，严格类型，避免 `any`。
- 格式与检查：Oxlint + Oxfmt；提交前执行 `pnpm lint`、`pnpm format`。
- 提交：建议用 `scripts/committer "<msg>" <file...>`，保持提交信息简洁、面向行为。
- 命名：产品/文档用 **OpenClaw**，CLI/包/路径/配置用 `openclaw`。

## 九、安全与运维要点

- **入站 DM 视为不可信输入**；默认依赖配对与 allowlist。
- 使用 `openclaw doctor` 和 `openclaw security audit --deep` 做配置与安全检查。
- Web 鉴权等凭证存于 `~/.openclaw/credentials/`；切勿提交真实手机号、密钥或生产配置到仓库。
- 文档与示例中使用明显占位符（如 `user@gateway-host`、假号码）。
